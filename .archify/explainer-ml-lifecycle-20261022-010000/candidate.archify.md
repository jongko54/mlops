# 머신러닝 수명주기 공부 기록 {#ml-lifecycle}

머신러닝은 학습 후에도 평가·배포·모니터링을 거쳐 계속 개선하는 과정으로 이해했음.

- 훈련에서는 데이터로 파라미터를 학습하고, 추론에서는 학습한 모델을 사용함.
- 검증 세트로 모델을 선택한 뒤 따로 둔 테스트 세트로 최종 성능을 확인함.
- 운영에서 문제가 보이면 원인을 확인하고 데이터와 모델을 다시 살펴야 함.[](source:mlops)

## 단계별로 무엇을 남겨야 하는지 정리했음 {#lifecycle-table}

| 단계 | 하는 일 | 남겨야 할 것·확인할 것 |
|---|---|---|
| 문제 정의 | 입력·출력과 성공 기준을 정함 | 목표 지표, 허용 오류, 비용·응답 시간 |
| 데이터 준비 | 수집·정제하고 필요한 레이블을 붙임 | 출처, 품질, 레이블 기준과 버전 |
| 데이터 분할·전처리 | 학습·검증·테스트를 나누고 입력 형태를 맞춤 | 누수 방지, 분할 기준, 전처리 코드 |
| 모델 학습 | 모델·설정을 정하고 파라미터를 학습함 | 코드·데이터 버전, 시드, 설정, 학습 로그 |
| 검증·모델 선택 | 검증 세트로 모델과 설정을 비교함 | 기준 통과 여부, 과적합, 오류 유형 |
| 최종 평가 | 선택한 모델을 테스트 세트로 평가함 | 최종 지표와 조건; 테스트로 반복 선택하지 않음 |
| 배포·추론 | 서비스나 배치 작업에서 예측함 | 모델 버전, 전처리 일치, 배포·복구 방법 |
| 모니터링 | 운영 상태와 입력 변화, 예측 품질을 확인함 | 지연·오류율, 자원 사용량, 드리프트, 정답 기반 성능 |
| 개선·재학습·종료 | 원인을 살펴 개선하거나 모델을 종료함 | 개선 근거, 재검증, 승격·롤백·보존 기준 |

## 평가와 운영 결과가 다음 학습에 이어진다고 이해했음 {#lifecycle-flow}

@callout level=note title="되돌아갈 지점은 원인에 따라 다름"
| 검증 실패 시 모델·설정뿐 아니라 데이터도 다시 확인해야 함. |
| 최종 평가가 기준에 못 미치면 배포를 보류함. 테스트 결과로 반복 튜닝하면 새로운 독립 평가 세트가 필요함. |
| 드리프트만으로 정확도 하락을 확정하지 않고, 정답을 모아 성능도 확인해야 함. |
| 모든 문제가 재학습으로 해결되지는 않음. 서비스 오류는 운영 조치가 필요할 수 있고, 필요 없어진 모델은 종료할 수 있음. |
