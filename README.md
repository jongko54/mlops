# MLOps 공부 기록

CH1·CH2를 보면서 머신러닝이 어떻게 학습하고 학습한 모델을 어떻게 운영하는지 정리했음. 내가 이해한 표현을 남겼고 개념이 섞였던 부분은 `(보충: …)`으로 붙였음.

## 머신러닝과 딥러닝

머신러닝은 데이터에서 가중치를 찾는 작업이라고 이해했음.

(보충: 신경망이나 선형 모델에서는 맞는 설명임. 좀 더 넓게 보면 데이터에서 패턴이나 규칙을 학습하는 과정임. 결정 트리처럼 가중치 대신 분기 기준을 학습하는 모델도 있음.)

딥러닝은 층을 깊게 쌓아서 복잡한 데이터의 특징을 학습하는 방식으로 이해했음.

(보충: 신경망 여러 개를 붙인다는 의미보다는 하나의 신경망 안에 여러 은닉층을 둔다는 의미에 가까움. 입력층·은닉층·출력층이라는 구분은 각 층의 역할을 뜻함. 이번 숫자 분류 실습은 은닉층이 하나인 작은 MLP를 사용했음.)

## 순전파와 역전파

처음에는 입력층·은닉층·출력층을 왕복하면서 가중치를 잡아가는 과정이라고 이해했음.

(보충: 순전파에서는 입력으로 예측값을 계산하고 역전파에서는 손실이 각 파라미터에 얼마나 민감한지 기울기를 계산함. 가중치와 편향을 실제로 갱신하는 일은 옵티마이저가 맡음. 입력값 자체가 층 사이를 왕복하는 것은 아님.)

학습 한 번의 흐름은 아래처럼 정리했음.

| 순서 | 하는 일 | PyTorch에서 연결한 부분 |
|---|---|---|
| 1. 기울기 초기화 | 이전 계산에서 쌓인 기울기를 비움 | `optimizer.zero_grad()` |
| 2. 순전파 | 입력층 → 은닉층 → 출력층으로 예측값을 계산함 | `prediction = model(x)` |
| 3. 손실 계산 | 예측값과 정답을 손실 함수로 비교함 | `loss = loss_fn(prediction, y)` |
| 4. 역전파 | 연쇄 법칙으로 가중치·편향의 기울기를 계산함 | `loss.backward()` |
| 5. 파라미터 갱신 | 계산한 기울기를 이용해 가중치·편향을 바꿈 | `optimizer.step()` |

현재 가중치로 예측하고 손실을 구하고 기울기를 계산해서 갱신하는 흐름을 반복한다고 이해했음. [PyTorch의 학습 루프](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)를 보면서 역전파와 갱신을 구분했음.

### 출력층

출력층에서 나온 예측값과 실제값의 차이로 손실을 계산한다고 이해했음.

(보충: 손실 계산은 역전파를 시작하기 전에 함. 또 손실은 단순한 뺄셈으로만 구하는 게 아니라, 회귀에서는 평균제곱오차, 분류에서는 교차 엔트로피처럼 문제에 맞는 함수를 사용함. 역전파는 그 손실을 미분하는 데서 시작함.)

### 은닉층

출력 쪽에서 전달받은 값에 활성화 함수의 도함수를 곱하면서 이전 층으로 전달한다고 이해했음.

(보충: 전달되는 것은 손실의 기울기임. 일반적인 완전연결층에서는 다음 층의 가중치도 계산에 들어감. 연쇄 법칙으로 각 층의 가중치 `w`와 편향 `b`에 대한 기울기를 구한 뒤 옵티마이저가 그 값을 이용해 파라미터를 갱신함.)

층이 깊을 때 시그모이드 같은 활성화 함수에서는 입력에 가까운 은닉층으로 갈수록 기울기가 작아지는 기울기 소실 문제가 생길 수 있다고 이해했음.

(보충: 작은 도함수를 여러 번 곱하면 앞쪽 층까지 전달되는 기울기가 아주 작아질 수 있음. 깊은 모델에서 무조건 발생한다는 뜻은 아니며 활성화 함수와 초기화 방식, 잔차 연결 등이 영향을 줌.)

### 입력층

처음에는 입력층이 오차를 받아 가중치를 업데이트한 뒤 역전파가 끝난다고 생각했음.

(보충: 일반적인 MLP의 입력층은 입력값을 전달하며 입력값 자체에는 학습할 가중치가 없음. 입력층에서 첫 은닉층으로 이어지는 연결의 가중치는 학습 대상임. 보통 모델 학습에서는 입력값에 대한 기울기까지 구할 필요는 없고 학습 대상 파라미터의 기울기를 구하면 됨. 토큰을 벡터로 바꾸는 임베딩처럼 학습 가능한 입력 변환은 별도로 구분해야 함.)

이 부분은 [PyTorch 자동 미분 설명](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)을 참고해 보충했음.

## 훈련 파이프라인과 인퍼런스 파이프라인

가중치를 조정하려면 훈련 파이프라인이 필요하고 입력 데이터는 텐서로 표현해서 모델에 넣는다고 이해했음. 텐서는 숫자를 여러 차원으로 담은 배열로 생각했음.

인퍼런스는 학습된 모델에 새로운 입력을 넣어 예측값을 얻는 과정으로 이해했음.

(보충: 학습된 응답을 그대로 꺼내는 방식보다는 학습한 파라미터로 새 입력의 출력을 계산하는 과정임. 이미지·문자열 같은 원본 입력은 전처리를 거쳐 텐서가 되고 모델 출력은 필요에 따라 숫자 클래스나 문장으로 후처리함. 일반적인 추론에서는 역전파나 가중치 갱신을 하지 않음.)

| 구분 | 훈련 파이프라인 | 인퍼런스 파이프라인 |
|---|---|---|
| 목적 | 데이터로 모델 파라미터를 학습함 | 학습한 모델로 새 입력을 예측함 |
| 흐름 | 데이터 준비 → 텐서 변환 → 순전파 → 손실 → 역전파 → 갱신 → 평가·저장 | 입력 → 전처리·텐서 변환 → 모델 실행 → 후처리·응답 |
| 남기는 것 | 모델 가중치, 설정, 데이터 버전, 평가 지표 | 예측 결과, 응답 시간, 오류·입력 통계 |
| 모니터링 | 손실, 검증 성능, 데이터 품질, GPU 사용량, 학습 실패 | 응답 시간, 오류율, 자원 사용량, 데이터 변화, 정답 확보 후 예측 성능 |

둘 다 모니터링이 필요하지만 봐야 할 지표는 다르다고 정리했음. 입력 데이터의 분포가 바뀌었다는 사실만으로 정확도가 떨어졌다고 확정할 수는 없고 정답을 모아 성능도 확인해야 함.

소프트웨어 스택도 역할별로 나눠서 이해했음. PyTorch 같은 프레임워크가 텐서 연산·자동 미분·옵티마이저를 제공하고 CUDA는 GPU 연산에 사용함. 여기에 데이터 처리, 실험·모델 저장, 실행 환경, 배포, 모니터링 도구가 붙는 구조임. 모든 도구를 처음부터 설치해야 한다는 의미는 아님.

## 파운데이션 모델, 사전훈련, 파인튜닝

파운데이션 모델을 정한 뒤 목적에 맞게 파인튜닝하는 방식이 있다는 것을 배웠음. 이미 학습한 모델을 출발점으로 쓸 수 있다는 뜻으로 이해했음.

처음에는 파인튜닝을 가중치 일부만 갱신하는 것으로 생각했음.

(보충: 전체 파인튜닝은 모든 파라미터를 갱신할 수 있음. PEFT는 일부 파라미터나 추가한 작은 모듈을 학습하는 방식임. LoRA는 보통 기존 가중치를 고정하고 가중치 변화량을 표현하는 작은 행렬들을 학습함. 따라서 일부만 갱신하는 것은 파인튜닝의 한 방식임.)

처음 적었던 “LLM 사전훈련은 이미 학습된 모델을 미세 튜닝하는 과정”은 아래처럼 구분해서 고쳤음.

| 구분 | 정리한 내용 | 데이터 예시 |
|---|---|---|
| 사전훈련 | 대규모 데이터로 범용적인 언어 패턴을 학습해 기초 모델을 만듦 | 대량의 텍스트에서 앞 토큰으로 다음 토큰을 예측 |
| 파인튜닝 | 사전훈련한 모델을 특정 작업이나 응답 방식에 맞게 추가 학습함 | 스팸 여부가 붙은 문장, 지시와 답변 쌍 |

(보충: 생성형 LLM의 다음 토큰 예측에서는 텍스트 자체에서 학습 목표를 만듦. 사람이 클래스 레이블을 붙이지 않아도 자기지도학습이 가능함. 레이블을 잘 만들어야 한다는 설명은 분류 같은 지도학습에 맞음. 사전훈련에서도 데이터 품질·중복·오염 관리가 필요함.)

파인튜닝 방식은 [Hugging Face PEFT 문서](https://huggingface.co/docs/peft/index), 사전훈련과 분류·지시 파인튜닝의 구분은 [LLMs-from-scratch 공식 저장소](https://github.com/rasbt/LLMs-from-scratch)를 참고했음.

### 클래스 레이블이 있는 데이터셋과 3단계

“3단계는 클래스 레이블을 가진 데이터셋”이라고 메모했음.

(보충: 이 문장만으로는 어떤 도표의 3단계인지 확정하기 어려움. 여기서는 LLM을 구현하고 사전훈련한 뒤 목적에 맞게 파인튜닝하는 흐름으로 이해해서 정리했음. 원래 도표의 단계 번호는 다시 확인할 부분임.)

분류 파인튜닝이라면 문장과 클래스 레이블의 쌍을 사용함. 예를 들어 메일 내용에 `스팸 / 정상`을 붙이는 식임. 지시 파인튜닝은 `질문 또는 지시 / 기대하는 답변`의 쌍을 사용함. 파인튜닝 데이터가 모두 클래스 레이블 형식인 것은 아니라고 정리했음.

### RLHF

RLHF는 인간 피드백 기반 강화학습이라고 이해했음.

사람이 모델의 답변을 비교하고 선호도를 표시하면 그 피드백을 이용해 모델이 선호되는 답변을 만들도록 학습하는 방식임.

(보충: 대표적인 흐름은 예시 답변으로 지도 파인튜닝 → 사람의 답변 선호도로 보상 모델 학습 → 보상을 이용한 강화학습임. 보통 사람이 매 응답마다 직접 점수를 주며 학습을 진행하는 구조는 아님. RLHF는 모든 파인튜닝에 반드시 포함되는 단계도 아님.)

[InstructGPT 논문](https://arxiv.org/abs/2203.02155)의 인간 피드백 학습 흐름을 참고했음.

## 머신러닝 수명주기

문제를 정하고 데이터를 준비한 뒤 학습·평가·배포·모니터링을 거쳐 다시 개선하는 흐름으로 정리했음. 아래 표는 일반적인 수명주기이며 모든 단계를 이번 실습에서 구현했다는 뜻은 아님.

| 단계 | 내가 이해한 작업 | 남겨야 할 것·확인할 것 |
|---|---|---|
| 문제 정의 | 풀 문제와 모델의 입력·출력, 성공 기준을 정함 | 목표 지표, 허용 오류, 비용·응답 시간 조건 |
| 데이터 준비 | 데이터를 수집·정제하고 필요한 레이블을 붙임 | 출처, 데이터 품질, 레이블 기준과 버전 |
| 데이터 분할·전처리 | 학습·검증·테스트를 나누고 입력 형태를 맞춤 | 데이터 누수 방지, 분할 기준, 전처리 코드 |
| 모델 학습 | 모델과 설정을 정하고 파라미터를 학습함 | 코드·데이터 버전, 시드, 설정, 학습 로그 |
| 검증·모델 선택 | 검증 세트로 모델과 설정을 비교함 | 기준 통과 여부, 과적합, 오류 유형 |
| 최종 평가 | 선택한 모델을 따로 둔 테스트 세트로 평가함 | 최종 지표와 평가 조건; 모델 선택에 테스트 세트를 반복 사용하지 않음 |
| 배포·추론 | 모델을 등록하고 서비스나 배치 작업에서 예측함 | 모델 버전, 전처리 일치, 배포·복구 방법 |
| 모니터링 | 운영 상태와 입력 변화, 실제 예측 품질을 확인함 | 지연·오류율, 자원 사용량, 드리프트, 정답 기반 성능 |
| 개선·재학습·종료 | 원인을 살펴 데이터를 보완하거나 재학습하고 필요 없어진 모델은 종료함 | 개선 근거, 새 모델 검증, 승격·롤백·보존 기준 |

데이터나 코드가 바뀌면 결과도 달라질 수 있으니 버전 관리와 모니터링은 여러 단계에 걸쳐 필요하다고 이해했음. 이 흐름은 [Google Cloud의 MLOps 설명](https://cloud.google.com/architecture/mlops-continuous-delivery-and-automation-pipelines-in-machine-learning)을 참고했음.

## 이번 실습과 연결해서 이해한 것

2026-10-21 e101의 RTX 4070 Ti에서 작은 숫자 분류 모델을 학습한 기록을 확인했음. `sklearn.load_digits`의 8×8 손글씨 이미지를 0~9로 분류한 실험이었음.

학습 1,078개, 검증 359개, 테스트 360개로 나눴고 검증 정확도는 약 95.54%, 테스트 정확도는 약 96.67%였음. 테스트 360개 중 348개를 맞힌 비율임.

(보충: 여기서 확인한 정확도는 해당 테스트 세트의 숫자 분류 정확도임. 실제 문서 OCR 정확도나 GPU 성능을 검증한 수치는 아님. 서비스 배포, 지속적인 운영 모니터링, 자동 재학습은 아직 구현하지 않았음.)
