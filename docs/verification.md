# 초기 구현 검증 기록

## 2026-10-21 e101 실제 GPU 검증

SSH `evo@10.31.10.101:8395` 경유로 e101에만 테스트 Job을 실행했다.
Job은 Complete(1/1), Pod는 Succeeded, 컨테이너 종료 코드는 0이었다.
RTX 4070 Ti / CUDA 12.6에서 검증 정확도 95.54%, 테스트 정확도 96.67%를 기록했고
저장 모델 재로딩도 통과했다. e102에는 작업을 생성하거나 기존 워크로드를 변경하지 않았다.

공식 PyTorch 런타임과 현재 커밋의 코드를 ConfigMap으로 결합한 테스트다.
저장소 Dockerfile로 만든 애플리케이션 이미지의 빌드·배포 검증과는 구분한다.
상세 실행 정보와 한계는 [GPU 테스트 기록](gpu-test-e101-2026-10-21.md)을 참고한다.

Namespace를 생성하지 않기 위해 서버 dry-run용 사본의 Namespace를 기존 `default`로
변환했다. 이 검사는 실제 `mlops-lab`의 정책, 스케줄링, 이미지 실행이나 스토리지 연결을
검증하지 않는다. 테스트용 이미지 digest는 스키마 검사용 값이며 실행 가능한 이미지가 아니다.

CPU 결과는 `artifacts/cpu-verification/`에 있으며 Git에서 제외된다.
최초 커밋 전에 실행했으므로 해당 실행의 `git_commit`은 `unknown`이다.
소스 SHA-256은 `9895286f7c3245a5b2951795679b5f1f785bab32f002e0726713bd22886f1156`이다.
검증 결과가 GPU 성능이나 실제 OCR 품질을 뜻하지 않는다.

## 초기 검사에서 남은 검증과 후속 상태

- Docker 정적 검사에서 amd64 베이스 이미지를 arm64와 비교하는 경고가 발생했다.
  `--platform linux/amd64`를 지정했지만 검사 결과는 실패였으며 원인을 확정하지 않았다.
- 2026-10-21 세션 권한 변경 후 Docker 소켓 접근이 거부되어 추가 확인이 중단됐다.
- 애플리케이션 이미지 전체 빌드와 레지스트리 push는 아직 수행하지 않았다.
  실제 GPU Job 실행과 PVC 읽기·쓰기는 위 2026-10-21 테스트에서 확인했다.
- e102의 GPU는 조사 시점 다른 실행 중인 워크로드가 점유하고 있었다.
- 초기 커밋 `0c090c8`의 [GitHub Actions checks](https://github.com/jongko54/mlops/actions/runs/39455171462)는
  성공 상태를 확인했다. 이후 커밋은 해당 커밋의 Actions 결과를 별도로 확인해야 한다.

## 원격 반영 경계

초기 조사에서는 GitHub와 Forgejo 모두 빈 저장소였다. 이후 제한된 실행 환경에서
두 원격 호스트의 DNS 해석에 실패했지만, 후속 push는 두 저장소 모두 성공했다.
초기 반영 커밋은 `0c090c88ded528b7843224bb3082d1f7bc3a3dcd`이며
GitHub는 기존 SSH 인증으로 반영했다. GPU 검증 기록과 학습 노트는 후속 문서 변경으로 관리한다.
각 변경의 원격 반영 여부와 CI 결과는 GitHub 커밋 및 Actions 기록에서 확인한다.
